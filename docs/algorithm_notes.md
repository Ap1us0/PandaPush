# PandaPush 算法笔记

## SAC 如何从接触数据学习

**Actor** 接收状态和目标，输出三维高斯分布的均值与标准差。训练时从分布可微地采样，经 tanh 得到 [-1, 1] 内的三维末端命令。演示时使用确定性动作。**Critic** 输入状态、目标和动作，用两个网络独立估计软 Q 值。计算目标与 Actor 更新时取较小值，减少高估。Critic 的目标网络缓慢跟随在线网络。

SAC 在累计奖励里加上熵项 `α H(π(·|s))`。策略希望采用 Q 值较高的动作，同时保持适量的不确定性以探索。Actor 最小化 `E[α log π(a|s) − min(Q₁,Q₂)]`。SB3 自动拟合熵温度 α。开始时用均匀随机动作填库，随后采样当前策略。初期较大的方差可能令末端抬高并绕过方块，从而减少接触经验。

**Off-policy** 指待优化策略可以利用旧策略与随机动作产生的转移。只要环境动力学和奖励定义一致，旧动作的实际后果就能监督 Q 值。Replay Buffer 环形存储 `(s, a, r, s', done, timeout)`，在训练时随机抽取小批，缓解相邻样本高度相关的问题。有限数据覆盖、函数逼近误差和策略分布变化仍会影响学习。模型保存网络和优化状态，经验单独保存到 replay buffer 文件。

## 目标和 HER

`achieved_goal` 是当前实际方块中心，`desired_goal` 是本回合指定的目标中心，二者都是世界坐标米。 `observation` 含归一化关节、末端、物体位置和速度，方块姿态、尺寸和剩余时限相关信息。策略的特征提取器再从目标字典计算相对向量 `g − x_cube`。

HER 从同一已结束回合中采样未来达成的位置当作新目标。例如原本瞄准 A，动作只把方块推到 B。如果重标目标 B，这次转移提供有用的成功样本。保持原动作和真实物理状态，把当前及下一状态的 `desired_goal` 都替换成 B，用 `compute_reward(next_achieved_goal, B)` 算虚拟奖励。 `future` 策略每条真实转移混合约四条虚拟转移。终止原因仅由动力学安全事件和时限决定，重标目标后仍然有效。3 步保持用于评估，瞬时位置用于奖励，历史保持计数不进入 Dict 状态。

稀疏奖励仅依赖方块到目标半径，目标内给 0，目标外给 -1，便于复用和重标。在随机探索很少推动方块时反馈有限，HER 也可能反复重标几乎静止的位置。稠密奖励 `−7d − 2.5 min(d_approach, 0.18) · 1[d≥r] + 0.35 · 1[d<r]` 引导末端寻找方块后方。每步接近成本为绝对距离，按方块方向计算，方块静止时不会产生正奖励。对难到达区域，后方位置引导可能仍不足以引出绕行。成功率用实际位姿独立评估。

当奖励在未达标时每步扣 1 分，智能体可能学会借安全终止缩短失败回合。修正版在安全终止的那一步收取剩余步数的代价 `−(H−t+1)`。这消除单纯提前结束所带来的扣分优势。HER 启用 `copy_info_dict`，让虚拟转移保留此终止代价，验证时保持物理成功判定一致。

## 从动作到物理推动

| 文件 | 输入和输出 | 原理与局限 |
| --- | --- | --- |
| `env.py` | Meta 配置、每回合种子、归一化增量 → Dict 观测、奖励、结束标志、接触及位移 | 给方块一个自由关节。reset 放置方块后，重力使其落桌。下一步状态来自 MuJoCo 对质量、惯量、执行器、接触的联立求解。目标位置按受限方向和距离随机化，初始工具姿态固定。 |
| `control.py` 和 `panda_cartesian.py` | 动作和当前测量位姿 → 桌面工作空间内目标 → 七关节参考 → 执行器输入 | 把动作映射为最大 4.5 cm 的矢量。构造 6×7 的位置及加权姿态 Jacobian。根据 SVD 调节 `σ/(σ²+λ²)`，对接近奇异的方向提高阻尼。每次用有限步的迭代改善近似解并限制关节角。PD 力矩加偏置补偿并限幅，然后逆向换算为 Menagerie 的 position-servo 控制输入。真实位移受阻尼、惯性和接触影响。 |
| `rewards.py` | 实际方块中心、目标、稠密模式的末端信息 → 标量或批量奖励 | L2 误差衡量目标完成度。后方点为 `x_cube − (r_pusher + r_cube) · dir_xy`。方块旋转后实际接触面会变化，此点是近似引导。 |
| `features.py` | Dict 中归一化后的状态和目标坐标 → 策略、Q 网络的特征向量 | 在 forward 中差分，使 HER 虚拟样本的目标向量自动一致。观测依赖模拟器提供的真值。 |
| `train.py` | 配置、训练种子、预算 → SB3 模型、经验、回合日志、独立开发评估 | 对 SAC 使用同一网络和更新频率。C 组更换官方 replay buffer。恢复 checkpoint 从新回合继续，随机状态和仿真内部状态不会按位恢复。 |
| `evaluate.py` | 模型或对照、场景种子 → 原始回合指标、成功率、接触力及失败分类 | 每个策略使用相同规则和场景。方块中心误差 <3 cm 连续 3 步，且在回合结束时仍满足才计成功。训练重复单位是独立训练 seed。 |

末端球和方块接触时，MuJoCo 解算出防止两物体穿透的法向约束力。接触点偏离方块质心会产生力矩，也可能旋转方块。接触之间的桌面摩擦消耗动能。桌面与方块的滑动系数在任务中以几何均值构成显式接触 pair，推动器与方块也各自配置了摩擦。较重的方块或较大摩擦通常要求更持续地施力，轻小低摩擦的方块可能滑过目标。积分步长、软接触参数和几何代理形状也影响这些现象。

**传统控制** 负责运动学、姿态保持、关节和力矩限幅及物理执行。**RL** 学习该向哪个方向走、怎样接近方块、推多久、什么时候停。规则基线由几何控制器单独运行，训练未读取基线动作和轨迹。

## 泛化与视觉

策略可能记住接触角度、目标分布、常见滑移距离和默认动作的制动效果。改变摩擦或几何会改变同一动作的后果。位置随机化覆盖工作区的一段连续扇区，物理属性配置用于分条件比较。固定的开发种子可用于选训练预算，最后另用较多冻结种子做交付评估。

视觉版本还需要用图像和本体感知估计方块与目标的位置、速度和接触状态，处理遮挡、相机标定和时延，并应对模拟渲染与现实成像的差异。实际机器人还要建模执行器/摩擦误差，检验安全边界和在感知不确定性下的动作效果。

## 自测题

1. 为什么 HER 虚拟转移需要替换当前及下一观测中的目标，同时用下一时刻的方块位置计算奖励？
2. 三维动作输出后的每一层分别使用什么单位，为什么真实 TCP 位移通常小于命令的 4.5 cm？
3. 如何从日志区分末端仅接近方块、发生接触、发生有效位移以及到达目标后滑出？
4. 若大多数随机回合没有移动方块，HER 会生成什么样的虚拟目标？这怎样影响稀疏奖励下的探索？
5. 如果同一策略在低摩擦桌面更常越过目标，应该看哪些时序信号验证原因？如何设计下一组对照？
